# TEOAE Signal Processing Orchestrator & Command Center

This repository contains the main entry code (`main.py`), which serves as the **GUI Orchestrator** (built with PyQt6) for a Transient-Evoked Otoacoustic Emissions (TEOAE) hearing screening system. 

Following a modular software architecture, all core Digital Signal Processing (DSP) and classification algorithms are encapsulated within an external module (`modul_analisisfix.py`). The main script orchestrates the pipeline execution and extracts key output parameters for real-time visualization and decision-making.

---

## Parameter Extraction & Pipeline Interface

The main script calls `modul_analisisfix.proses_data_oae()` and extracts the following key parameters generated by the underlying signal processing pipeline:

### 1. `fig` (Matplotlib Plot Object)
* **Pipeline Source:** Reconstructed TEOAE waveform generated after time-domain buffer averaging (Buffer A & Buffer B).
* **Usage:** Rendered directly onto the PyQt6 custom canvas to display the acoustic response waveform with a high-contrast dark theme.

### 2. `status` (Primary Screening Result)
* **Pipeline Source:** Final decision thresholding block combining RAD2D, SNR, and WWR evaluation metrics.
* **Usage:** Drives the primary diagnostic indicator on the dashboard (**PASS** / **REFER**).

### 3. `snr_data` (Frequency-Binning Matrix)
* **Pipeline Source:** Signal-to-Noise Ratio (SNR) and background noise computation across target frequency bands.
* **Usage:** Populates both the real-time SNR vs. Noise bar chart and the detailed numerical frequency readout grid.

### 4. `wwr` (Wavelet Window Ratio)
* **Pipeline Source:** Time-frequency energy concentration metric calculated via Continuous Wavelet Transform (CWT) binary masking.
* **Usage:** Rendered as a prominent percentage indicator on the user interface.

### 5. `csc` (Cross-Spectral Coherence)
* **Pipeline Source:** Signal validation block evaluating phase and spectral consistency between Buffer A and Buffer B.
* **Usage:** Validates recording quality to ensure clinical relevance.

### 6. `rad_dist` (RAD2D Classification Distance)
* **Pipeline Source:** Rule-based decision engine acting on non-linear Recurrence Quantification Analysis (RQA) features—Entropy (ENT), Determinism (DET), and Recurrence Rate (REC)—reduced via Principal Component Analysis (PCA).
* **Usage:** Provides the quantitative evaluation distance metric against the classification threshold (`≤ 2.47` for Pass).
